## 4. 智能问答（核心功能）

智能问答不是“聊天机器人”，而是 **SRE 工作流引擎**：

- **把需求变成计划**：明确目标→拆解步骤→生成命令与验证点
- **把计划变成执行**：对接主机，按步骤执行（需你授权）
- **把执行变成沉淀**：自动总结结果、输出复盘与改进建议，并可存入知识库

### 4.1 两种模式：方案咨询 vs 排障与部署

- **方案咨询**：
  - 适合：先要“正确方向”、架构/方案/命令清单、风险点、回滚策略
  - 输出：可执行的 SOP、命令模板、检查项、告警与回滚

- **排障与部署（授权执行）**：
  - 适合：需要真实在机器上执行、验证、修复、交付
  - 输出：执行计划（分步骤）→ 你确认后执行 → 回显结果 → 自动总结

> 关键原则：**AIOps+ 负责“想清楚并做完”，你负责“把关与验收”。**

### 4.2 你要怎么提需求（高成功率模板）

把问题描述成 4 件事：

1. **目标**：你想要什么结果（例如：3 Master + 3 Worker 的生产 K8S）
2. **环境**：系统版本、网络、权限、现有组件（例如：Ubuntu 22.04 / 内网 / 有 sudo）
3. **约束**：公司规范/端口/镜像仓库/不允许停机窗口等
4. **验收**：你要如何确认完成（例如：kubectl 可用、核心组件 Ready、提供验收清单）

推荐提问模板：

```text
目标：……
环境：……
约束：……
验收：……
请给我：执行计划 + 风险点 + 回滚方案 + 验收清单
```

### 4.3 智能问答里的“核心模块”

#### A. 需求澄清与边界确认
- 让 AIOps+ 先问你 5-10 个关键问题（网络、权限、依赖、SLA）
- 没澄清前不盲目执行

#### B. 方案与执行计划生成
- 输出：
  - 步骤清单（按先后顺序）
  - 每一步的命令、预期输出、失败判定
  - 风险提示与回滚方式

#### C. 授权执行与结果回显
- 你每一步确认后才会执行
- 执行后给出：输出、错误、退出码（用于自检）

#### D. 失败自检与修正
- 失败会先解释原因：权限/依赖/网络/配置
- 再给出修复步骤与再次执行方案

#### E. 总结与沉淀
- 输出总结：做了什么、为什么这么做、下一步建议
- 支持一键存入知识库（形成 SOP）

## 5. 排障与部署：如何交付复杂系统（示例）

下面以“复杂交付”为例，展示你与 AIOps+ 的协作方式。

### 5.1 部署生产 K8S 集群（示例流程）

建议你这样下单：

```text
目标：部署生产 K8S（3 Master + 3 Worker），支持高可用与滚动升级
环境：6 台新机器 Ubuntu 22.04，内网互通；有 sudo；可访问公司镜像仓库
约束：使用 containerd；CNI 用 Cilium；Ingress 用 Nginx；证书有效期 1 年
验收：kubectl 正常；核心组件 Ready；提供 kubeconfig；给出验收清单与回滚方案
```

AIOps+ 典型交付会包含：

- **前置检查**：时间同步、内核参数、swap、端口冲突、DNS/NTP
- **运行时安装**：containerd + crictl
- **kubeadm 初始化**：控制平面初始化、证书/etcd 参数
- **网络插件**：Cilium 安装与验证
- **加入节点**：worker join、污点/标签
- **基础组件**：metrics-server、ingress、storageclass（如有）
- **验收清单**：节点/Pod/Service/网络连通/镜像拉取
- **回滚方案**：kubeadm reset、清理目录、恢复前状态

> 你要做的：每一步看清楚计划与风险，确认后授权执行，最后按验收清单验收。

### 5.2 部署数据库集群（MySQL/PostgreSQL 等）

适合 AIOps+ 交付的内容：

- 架构选择：单主多从 / MGR / Patroni / Proxy
- 参数与容量：连接数、buffer、慢查询、备份策略
- 高可用：VIP、Keepalived、故障切换演练
- 备份恢复：全量/增量、演练恢复到指定时间点
- 监控告警：QPS、延迟、复制延迟、磁盘水位

你可以这样提：

```text
目标：部署 MySQL 8.0 三节点（高可用），读写分离
环境：3 台机器，磁盘 2TB；内网；有 sudo
约束：必须开启审计；备份保留 30 天；允许维护窗口每周一次
验收：主备切换演练通过；备份恢复演练通过；监控告警齐全
```

### 5.3 部署中间件集群（Redis/Kafka/ES/Nginx 等）

AIOps+ 会按“生产标准”交付：

- 节点规划：副本数/分片/容量/网络
- 配置治理：参数、持久化、限流、TLS
- 可观测：监控、日志、告警
- 演练：故障节点下线、扩容、滚动升级

### 5.4 复杂问题排查（生产故障）

建议你按“现象→影响→变更→时间线”描述：

```text
现象：接口 P99 从 200ms 升到 3s
影响：xx 服务 5xx 增加，订单失败率 2%
变更：今天 10:30 发布了 v1.2.3
时间线：10:35 开始变慢，10:50 达到峰值
补充：Grafana 链接/关键日志片段/机器列表
```

AIOps+ 的排障套路通常是：

1. **确认范围**：单机/单 AZ/全局？
2. **快速止血**：降级、限流、回滚、摘流
3. **定位瓶颈**：CPU/内存/GC/IO/网络/依赖超时
4. **验证假设**：用命令与监控数据证据闭环
5. **修复与复盘**：修复动作 + 复盘文档 + 改进项（进入知识库）

## 6. 主机管理

主机管理用于“把 AI 方案落地到机器”。

- **新增主机**：
  - **手动添加**：填写 IP/端口/用户名/密码 或 **SSH 私钥**
  - **云主机同步**：支持 **腾讯云 / 阿里云 / 华为云 / 京东云 / 天翼云** 等主流公有云，填写 AK/SK 即可一键导入
  - **堡垒机同步**：支持 **Jumpserver / Spug / Teleport** 等主流开源堡垒机，填写 URL/Token 即可接入
- **连接测试**：验证连通性与权限（建议先测再执行）
- **授权执行**：排障与部署会基于主机列表下发命令

建议：
- 使用最小权限账号（必要时 sudo）
- 生产环境建议开启堡垒机/审计策略

## 11. 最佳实践（强烈建议）

- **先方案后执行**：复杂系统先走“方案咨询”，确认无误再进入“排障与部署”执行
- **给约束**：镜像仓库、端口、合规要求、SLA、维护窗口，越清晰越快
- **每一步验收**：让 AIOps+ 给每一步的“预期输出/失败判定”
- **沉淀 SOP**：成功一次就写入知识库，下次直接复用

## 12. 常见问题（FAQ）

### Q1：我不会运维，也能用吗？

可以。你只要能把“想要什么结果”描述清楚，AIOps+ 会把过程拆解成你能审核的步骤，你按提示授权执行即可。

### Q2：为什么要“授权执行”？

为了安全：任何对生产的改动都必须由你确认，避免 AI 误操作。

### Q3：复杂交付要多久？

取决于环境与约束。建议先让 AIOps+ 做需求澄清与计划评估，再估算工期与风险。
